# CUDA 12.8/13.0 Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Phase 1 select, install, and validate PyTorch 2.9.1 for either CUDA 12.8 or CUDA 13.0 before any experiment stage runs.

**Architecture:** A small shell helper owns the supported CUDA-to-index mapping and dependency fingerprint. A Python preflight module owns runtime metadata validation and the real KIVI GPU roundtrip. The existing launcher composes both components while the offline entrypoint continues to use a pre-staged environment without Git or network access.

**Tech Stack:** Bash, Python 3.10, PyTorch 2.9.1, Triton through the pinned KIVI checkout, pytest.

## Global Constraints

- Support exactly `cu128` and `cu130`; default to `cu128`.
- Install exactly `torch==2.9.1` from the matching official PyTorch index.
- Keep `scripts/run_phase1_offline.sh` Git-free and network-free.
- Do not commit CUDA wheels, model checkpoints, embeddings, or datasets.
- Do not silently fall back to CPU, another CUDA variant, or another quantization backend.
- Run a real KIVI quantize/dequantize operation during CUDA preflight.
- Preserve the existing strict Origin-cache validation and strict KIVI materialization behavior.

phase1_cuda_runtime_version() {

    cu128) printf '%s\n' "12.8" ;;
    cu130) printf '%s\n' "13.0" ;;

}
